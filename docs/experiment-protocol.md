# 实验、证据与验收规范

本课程供熟练模拟 IC 工程师研修，读完课文后能规划和执行实验；工程最终绑定、按钮名称与求解器参数以本机版本和新网表为准。完整课程已准备不代表任何实验已经跑通。

## 运行前：让实验可重建

每次只回答一个工程问题。先写假设、预期方向和反证：例如“加长采样窗口应降低输入相关的残差；若无变化，优先检查本次改变是否进入实际网表”。同时预先约定测量定义、阈值与来源，避免看过结果后再改变通过条件。

在 EDA 主机使用恢复副本，记录复制范围、日期、原包 SHA-256 与当前工作副本差异。复制 testbench 不会自动隔离下层 DUT；改下层 cell 时需复制相应层级并核对 master 引用。ADE 设置、副本库、行为模型和外部 include 均属于变更范围。

机器路径来自 `config/local.env`，许可证和连接凭据留在本机。第一课仍以检查为主；本次完整课程编写不要求启动或保存任何 EDA 会话。

## 一次运行的最小身份

| 项目 | 必须记录的内容 |
| --- | --- |
| 输入身份 | 原包校验、工作副本版本/差异、library/cell/view、test、corner、实际 view 绑定 |
| 工具条件 | 主机别名、Virtuoso/Spectre/数字仿真器版本、许可证或编译阻塞 |
| 仿真条件 | 供电、温度、模型 section、统计开关/种子、激励、分析、时间步/误差设置、保存选项 |
| 运行身份 | 新 history/run ID、开始日期、输出目录、日志、网表与外部模型的 SHA-256 |
| 测量条件 | 信号与节点名、阈值、窗口、采样/插值方法、点数、单位、脚本或表达式版本 |
| 结论 | 实测值、判据、通过/失败/阻塞/未执行、可支持的设计结论 |

将四类数据分开写：**文件保存值、当前会话值、推导值、实测值**。工程历史结果可以用来研究测量表达式，必须注明原作者/历史运行，不能当作当前实验通过。

## 运行顺序

1. 确认目标会话、工作目录与 test，保存恢复副本。
2. 核对当前设置；通过当前版本已验证的 GUI/API 生成新网表，追踪模型与行为源文件。对模型 include 递归校验，避免只哈希顶层包装文件。
3. 在实验副本中保存本次 ADE 设置，赋予新运行身份。GUI/API 的具体方法查当前 bridge checkout 和本机文档，不从课文猜 SKILL 命令。
4. 先跑能回答问题的短实验，再决定是否增加时长或角落。求解器完成与设计符合规格分别判定。
5. 检查日志、收敛、缺失信号、码解码及窗口，随后计算指标。
6. 改变一个因素时保留同条件基线。必要的数值收敛检查只在新设置、异常或精度疑问时增加，形成误差上界后停止无目的重复。

## 阈值与数值精度

阈值应来自规格、已有设计预算或明确声明的课程实验判据。没有规格时允许得到“测得某值，产品通过条件待定”，不把教学用阈值冒充芯片要求。比较两个结果需报告差值和测量/数值不确定性；差值与不确定性相当时结论为尚不能区分。

| 结果类型 | 处理方式 |
| --- | --- |
| 仿真错误或缺模型 | 记 blocked，留日志与最小复现条件 |
| 求解器成功但指标越限 | 记设计/测量失败，先核对实验有效性 |
| 信号、点数或单位错误 | 记测量无效，修复后重新测量或重跑 |
| 条件一致且判据满足 | 记该条件下通过，注明模型覆盖范围 |
| 没有运行 | 记未执行，保留预测与实验计划 |

## 保存与续学

Git 保存课文、记录表、自编脚本、少量 CSV/JSON/图片摘要；OA、PDK、完整网表包和大波形留在服务器。摘要引用主机别名、相对于教材/运行目录的路径、run ID 和哈希。共享文件中不记录连接凭据或许可证值。

结束时填写本课笔记并更新 [progress.md](../progress.md)。记录本次实际完成的步骤，以及下一项能直接执行的操作。完整章节的教学参考推导不能填成学员的原预测。

## 课程验收与产品验收

课程验收关注：测量是否定义清楚、实验是否可重建、证据是否能支持因果判断、模型边界是否说得准确。产品验收关注在规定条件下是否满足规格。一次模型较理想的仿真可完成课程任务，但产品结论应限制在模型包含的效应范围内。
