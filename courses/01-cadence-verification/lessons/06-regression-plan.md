# 第 06 课：把 ADC 工程变成可执行的回归计划

**工程问题：** 哪些证据足以支持一次设计变更，哪些测试只是在重复计算？建议两次 60–90 分钟研修。

前置：第 02–05 课至少各有一项有效证据；未执行项可以进计划，但不能填通过。记录：[第 06 课](../../../notes/06-regression-plan.md)。状态：计划课已准备。

## 1. 预测

假设仅修改 CDAC 桥接电容，哪三项测试最能发现功能、线性与速度回归？若修改行为控制器的延迟，原先 SNDR 通过是否足够？先给最小测试集合和遗漏风险，再阅读原 run plan。

## 2. 阅读现有计划而非照单全跑

入口 `saradc/10Bit_ADC_Run_Plan/maestro`，已核实保存 view 存在。枚举当前 active tests、禁用 tests、corner、sweep、统计设置、表达式和 pass/fail 阈值。记录每个 test 的 design master；相似名称不代表同一个 DUT。

检查表达式是否依赖历史路径、未保存波形、旧 FFT 长度或陈旧的 `f_fftbin`；比较性能指标与第 03 课独立算法定义。计划中的默认阈值若无规格来源，标记“待追溯”，不要自动当作设计要求。

## 3. 建立需求—机制—测试—证据矩阵

| 需求/风险 | 候选测试 | 核心观察 | 判据来源 |
| --- | --- | --- | --- |
| 基本转换功能 | `10Bit_ADC_TB_new` 的短 nominal | 两段采样、十次决策、DR、稳定码 | 控制链与功能要求 |
| 动态精度 | 同 TB 经审计的单音测量 | 解码、窗口、SNDR/SFDR | 输入条件下的系统预算 |
| 静态转移完整性 | 从当前 TB 建立的低速扫输入实验副本 | 缺码、单调性、DNL/INL | 明确量程、endpoint/best-fit 定义 |
| DAC 误差和建立 | `10Bit_capdac_TB_new` | 关键进位、桥接/权重、决策前残差 | 模块预算与实际拓扑 |
| 比较器边界 | 已确认匹配 master 的比较器 TB | nominal 判决、失调、动态噪声 | 共模、过驱动、判决期限 |
| 条件覆盖 | 已选择的 PVT/统计运行 | 失败率、裕量、收敛分类 | 模型范围和置信目标 |

这里的静态转移测试是新实验设计，不宣称工程已附带对应 run plan。DNL/INL 必须定义实际码范围、转移阈值、端点或拟合口径；低速扫输入可隔离动态效应，仍需每个点有足够采样/转换等待时间。若用码密度法，刺激分布、样本量和端点处理另作审计。

## 4. 依风险建立三个运行层级

- **Smoke：** 新绑定/编译/短功能时序，迅速发现缺模型、无转换和码读出错误。
- **针对变更的回归：** 与改动机制直接相关的模块、系统指标及一个容易受牵连的边界条件。
- **里程碑覆盖：** 已确定的输入频点/幅度、PVT、统计和长期性能；用于版本评审，按证据缺口安排计算。

层级由风险决定，不以“角落最多”为优。短测试通过后再分配长仿真；失败时保留本次 run 身份，修复后重跑受影响项。历史结果可以比较趋势，须匹配配置、工具、测量定义和模型。

## 5. 一次可执行的回归演练

1. 以一个真实或拟议的变更填写影响清单：DUT、模块边界、参数、负载、控制和测量。
2. 冻结基线网表/设置和测量版本，确定通过阈值、预期差值与数值误差容差。
3. 运行一个 smoke 和一个针对变更的测试；若当前仅有计划，记未执行，列清运行条件。
4. 比较修改前后相同输入条件下的值、差值和不确定性。随机运行需说明配对种子与独立样本的不同用途。
5. 对失败附局部时序/残差、日志或表达式证据；区分工具故障、测量无效和设计失败。

## 6. ADC 单元评审

交付一份简短评审，必须回答：

1. 当前可签字的功能、速度、精度与统计结论分别是什么，条件和模型边界是什么？
2. 最重要的失效机制是什么，哪次受控实验支持它？
3. 回归矩阵中哪些项已通过、失败、阻塞或未运行？
4. 下一项设计变更如何验收，有哪些未覆盖风险？

验收：矩阵中的每个通过项都能定位到实际运行；阈值与需求关联；变更影响对应最小回归集合；存在明确的未知项。课程 ADC 单元完成需有学员判断和实验记录，文件存在不计完成。
