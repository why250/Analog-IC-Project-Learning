# 第 02 课：建立可复现的 nominal transient 基线

**工程问题：** 怎样证明这次波形来自当前配置，并验证 ADC 确实按预期完成转换？建议两次 60–90 分钟研修，仿真时间另计。

前置：[第一课](01-project-map.md) 和 [采样控制入口](01a-sampling-entry.md) 的静态地图；首次运行按 [证据规范](../../../docs/experiment-protocol.md)。记录：[第 02 课](../../../notes/02-nominal-baseline.md)。状态：课文已准备，实验未执行。

## 1. 预测：先定义要看见的时序

先写下 `sample` 高电平宽度、相邻采样起点间隔、`DR` 与输出更新的关系。如果输出位在 `DR` 边沿后仍经历 transition，哪个相位能读到稳定码？启动后第一笔结果和第几笔开始稳态是否一定相同？

上课时先检查预测，再阅读下面参考。已静态追踪到 `I0/I56/I22` 的行为控制器；按稳态源码推导两段采样与十段比较。以保存 `fclk=1.2 GHz` 计算，内部周期约 833.33 ps，采样高电平约 1.667 ns，循环约 10 ns。传播延迟、启动和实际 view 绑定仍须实验验证。

## 2. 入口与基线配置

采用 `saradc/10Bit_ADC_TB_new/maestro`，其 design 入口为同 cell 的 `schematic`。当前文件 active test 名为 `saradc:10Bit_ADC_TB_new:1`；到运行时重新确认 test 名，避免将历史名称当成当前会话身份。

| 项目 | 首个基线的处理 |
| --- | --- |
| 激励 | 先保持保存变量和电路连接，不同时改输入频率、幅度与时钟 |
| 统计 | 确认运行模式及实际网表；`section=mc` 本身不代表启动随机抽样 |
| transient noise | 首个时序实验关闭随机瞬态噪声；具体选项按当前 ADE/Spectre 文档核对 |
| 模型 | 先查现有 section 对 nominal 参数的实际定义，不擅自用名称判断工艺角 |
| 仿真时长 | 先覆盖启动及至少若干稳定转换；如 0.5–1 µs 可作教学起点，是否足够由稳定性证据决定 |
| 输出目录 | 指向本次实验副本的独立目录，使用新 history/run ID |

缩短 stop time 是实验设置变化，保存于副本并记录。课 03 再建立足够长的频域记录；这里先用短仿真验证时序，节省无效计算。

## 3. 新网表审计

从当前会话生成新网表，至少核对以下内容：

1. DUT 是否仍为 `saradcII/10bit_adc_core_w_split_dac_ld1_msb`；控制器和门是否选择了预期 `veriloga`，比较器/开关采用哪些实现。
2. 模型 include 是否存在，section 名与参数一致；记录控制器源码和关键模型身份。
3. `CLK` 周期、`SC` 长脉冲、输入源频率/相位/幅度，以及输出 bus 的真实展开顺序。
4. transient 的实际 stop、误差选项、保存节点及是否含 `montecarlo` 或随机噪声设置。

把 schematic 路径映射到网表节点，不直接假定 `I0/I56/...` 是可供 Spectre 保存的名字。保留网表哈希和路径；旧网表存在不代表新配置进入了运行。

## 4. 用两种观察粒度看同一次运行

| 粒度 | 保存/观察对象 | 目的 |
| --- | --- | --- |
| 边沿及时序 | 顶层 `SC/CLK/data_ready`，内部 `clk_dly/sample/sample_clkb`，比较器输入/输出、逐位控制 | 查启动、两段采样、十次决策和裕量 |
| 稳定码 | 输出各位与 `DR`，有效码读出相位 | 为后续解码建立时刻定义 |

保存的 `strobeperiod=10n` 与转换周期相当，单独保留这种抽取不足以观察 833 ps 内部周期。用能够保留内部边沿的信息检查时序；FFT 所需等间隔码序列可之后从同次高分辨率数据抽取。不要将仅用于 FFT 的采样设置当作电路事件解析精度。

为比较器决策预留可测量的窗口：从 DAC 控制变化，到比较器输入进入误差预算，再到决策被控制器采集。`maxstep`、误差容限、waveform 存储和 `transition()` 参数共同影响观察；提高存储采样率不能弥补求解器本身未解析关键事件。

## 5. 实验与证据

1. 在副本保存本次设置，启动新的短 nominal transient，记录精确 history。
2. 检查运行日志的编译、模型、收敛与结束状态。先确认模拟结果存在，再寻找有效码。
3. 标记一次启动段和至少三轮稳定转换：采样开始/结束、每次判决、`DR`、输出稳定。
4. 按实际输出极性和 bus 排序建立码解码映射。稳定码时刻必须在所有位过渡完成之后、下一次锁存之前。
5. 在有精度疑问的局部时间段，用更严格的数值设置复核边沿或残差；若差异显著，先解决数值不确定性。

保存一张局部时序图与一张事件表，事件表包含轮次、采样时刻、最后决策、DR 时刻、码读出时刻和实际码。相邻稳定采样时间的差值应支持采样率判定；单凭参数 `fsample` 不足以做到这一点。

## 6. 验收与失败定位

验收要求：结果属于本次配置；实际模型绑定已核实；多轮连续转换的采样、决策及锁存关系与控制器一致；稳定码相位已定义。报告测得周期和偏差，容差来源为时间解析精度与模型延迟，不能只写“看起来正常”。

| 现象 | 优先核对 |
| --- | --- |
| 无转换 | `SC` 上升阈值、控制器初始化、时钟是否进入实际 master |
| 只有一次输出或输出重复 | 周期测量、state 推进、保存信号与解码时刻 |
| 码出现大跳变 | bus 排序、位阈值、同时更新时读码、输入是否越量程 |
| 两段采样不符 | 当前控制器 view、门延迟、采样信号是否取错层级 |
| 日志成功但信号缺失 | 保存设置、精确 history、实际节点名 |

**设计判断：** 行为控制器时序成立，能支持哪类功能结论？晶体管实现的数字时序、亚稳态和时钟抖动是否已覆盖？下一课用已验证的码相位审计 SNDR。
